## 0. 먼저 — iPhone 전용으로 고정했다

`TARGETED_DEVICE_FAMILY = 1` (iPhone). 이유:

- iPad 를 지원한다고 표시하면 **iPad 스크린샷을 따로 올려야** 하고,
  심사에서 **iPad 화면 깨짐으로 반려되는 일이 흔하다.** 이 앱 UI 는 폰 기준으로 만들었다.
- iPhone 전용이어도 iPad 에서 **호환 모드로 설치·실행된다.** 사용자가 못 쓰는 게 아니다.

⚠️ 이 설정을 바꿨으니 **Archive 를 다시 만들어야** 반영된다.

## 1. 스크린샷 — 어떤 화면을 올리나

### 크기
**iPhone 6.9" 하나만 올리면 된다.** 나머지 크기는 애플이 자동으로 줄여서 보여준다.

| 필요 | 해상도 | 찍는 기기 |
|---|---|---|
| iPhone 6.9" (필수) | 1290×2796 또는 1320×2868 | iPhone 16/17 Pro Max 실기기 또는 시뮬레이터 |

- 최소 1장, **최대 10장**. 실질적으로 **4~6장**이 적당하다(사용자는 앞 3장만 본다).
- 상태바가 지저분하면 안 된다 → 시뮬레이터로 찍는 편이 깔끔하다.

### 찍는 법 (시뮬레이터가 제일 편하다)
```bash
cd ~/StudioProjects/routefinding/app
npx react-native run-ios --simulator="iPhone 17 Pro Max"
```
시뮬레이터에서 `⌘S` → 바탕화면에 저장된다. (기기 프레임 없이 화면만 저장된다 — 그게 맞는 형식이다)

### 어떤 화면을 올릴까 — **이 순서를 권한다**

| # | 화면 | 왜 |
|---|---|---|
| 1 | **지도 탭** — 마커가 여러 개 보이는 상태 | 한 장으로 "무슨 앱인지" 전달된다. 첫 장이 가장 중요하다 |
| 2 | **개념도 상세** — 사진 위에 등반 라인이 그려진 것 | 이 앱의 핵심 가치. 경쟁 앱과 다른 점 |
| 3 | **개념도 검색 결과 목록** | 데이터가 많다는 걸 보여준다(5,400개 루트) |
| 4 | **루트제보 작성** 또는 **사진에 라인 그리기** | 사용자가 기여할 수 있다는 점 |
| 5 | **등반일지 / 마이페이지** | 기록이 남는다는 점 |

**찍기 전에 준비할 것**
- 로그인 상태로, **실제 데이터가 보이는 화면**을 찍는다 (빈 목록/더미 데이터 금지 — 심사에서 지적된다)
- 개인정보가 화면에 없게 한다 (다른 사람 이메일·닉네임 등)
- 지도는 **북한산·인수봉처럼 마커가 모여 있는 곳**으로 맞춰 찍으면 밀도가 좋아 보인다

> 스크린샷에 글자(설명 문구)를 얹는 건 선택이다. 없어도 심사에 문제없다.

## 3. ⚠️ 개인정보처리방침 URL — **없으면 제출이 안 된다**

웹 프로젝트(`routefinding-web`)에 개인정보처리방침 페이지가 **없다.**
Play Console 에는 이미 등록돼 있을 것이므로(구글도 필수) **그 주소를 그대로 쓰면 된다.**
Play Console → 정책 → 앱 콘텐츠 → 개인정보처리방침 에서 확인할 것.

없다면 웹에 정적 페이지를 하나 만들어 Firebase Hosting 에 올리면 된다.
**반드시 담아야 하는 내용**: 수집 항목(이메일·닉네임·위치·사진), 이용 목적, 보관 기간,
**제3자 제공(Google AdMob 광고 식별자)**, 파기 절차, 문의처.

## 4. 앱 개인정보(데이터 수집) 설문 — AdMob 때문에 필수

App Store Connect → **앱이 수집하는 개인정보** → 편집.

이 앱에 해당하는 것:

| 데이터 | 수집? | 용도 | 사용자와 연결됨? | 추적? |
|---|---|---|---|---|
| 이메일 주소 | 예 | 앱 기능 (로그인) | 예 | 아니요 |
| 사용자 콘텐츠 (사진·제보·등반일지) | 예 | 앱 기능 | 예 | 아니요 |
| 대략적/정확한 위치 | 예 | 앱 기능 (지도·루트 좌표) | 예 | 아니요 |
| **기기 ID (광고 식별자)** | 예 | **제3자 광고** | 아니요 | **예** |
| 사용 데이터 (제품 상호작용) | 예 | 분석·광고 | 아니요 | 예 |

⚠️ 기기 ID 를 **"추적"** 으로 표시하면 애플은 보통 **ATT 팝업**을 기대한다.
우리는 ATT 를 넣지 않았다(비개인화 광고로 나간다). 그래서 **"추적: 아니요"** 로 두는 편이
현재 구현과 일치한다 — 광고 SDK 는 들어 있지만 우리가 추적 권한을 요청하지 않으므로
개인화 추적을 하지 않는다. **문항은 애플이 자주 바꾸니 화면 문구를 읽고 판단할 것.**

## 5. 🚨 심사 정보 — **테스트 계정을 반드시 넣어야 한다**

이 앱은 **로그인해야 아무것도 볼 수 없다.** 심사자가 못 들어가면 **100% 반려된다**
(가장 흔한 반려 사유다).

App Store Connect → 앱 심사 정보 → **로그인 필요** 체크 → 계정 입력:
```
사용자 이름: (심사용 계정 이메일)
암호:        (비밀번호)
```
- **심사 전용 계정을 하나 새로 만들어** 넣는 것을 권한다 (관리자 계정을 주지 말 것)
- 그 계정으로 **실제 로그인이 되는지 직접 확인**하고 넣을 것
- 메모란에 한두 줄: "클라이밍 루트 정보 앱입니다. 로그인 후 지도/개념도 탭에서 루트를 볼 수 있습니다."

## 6. 연령 등급

설문에 답하면 자동 산정된다. 이 앱은 대부분 '없음'이며,
**사용자 생성 콘텐츠(사진·제보)** 항목이 있으므로 그에 맞게 답한다.
→ 보통 **4+ 또는 12+** 가 나온다.

---

## 7. 제출 순서

```
① TARGETED_DEVICE_FAMILY 반영해 Archive 다시 → 업로드
② TestFlight 로 본인 확인 (지도·로그인·광고)
③ 스크린샷 5장 업로드
④ 메타데이터 + 개인정보처리방침 URL
⑤ 앱 개인정보 설문
⑥ 심사 정보에 테스트 계정  ← 빠뜨리면 반려
⑦ 연령 등급 설문
⑧ 빌드 선택 → '심사에 추가' → 제출
```

심사는 보통 **1~3일**. 반려되면 사유를 그대로 알려주면 대응한다.
