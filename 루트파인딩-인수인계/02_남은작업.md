## P0 — 지금 바로

### 1. iOS Xcode 실기기 빌드 검증
`pod install` 통과했고 빌드만 남았다.

```bash
open ~/StudioProjects/routefinding/app/ios/RouteFinding.xcworkspace
```
- ⚠️ `.xcodeproj` 말고 **`.xcworkspace`**
- Signing & Capabilities → Automatically manage signing, **Team 선택**
- Bundle ID `com.yusungyun.RouteFinding`
- **Product → Scheme → Edit Scheme → Run → Build Configuration = `Release`**
  (Metro 없이 실기기 단독 실행)
- `⌘R`

**빌드 깨지면 임의 패치 금지.** 에러 원문을 `docs/06_iOS_BUILD_NOTES.md` §2 표에 누적 기록.
(그 문서에 1~3차 실패 이력이 있다. 같은 실수 반복 방지용)

### 2. 안드로이드 실기기 APK
```bash
cd ~/StudioProjects/routefinding/app/android
./gradlew assembleRelease
# → app/build/outputs/apk/release/app-release.apk
```

## P1 — 앱을 웹 수준으로 (핵심 작업)

**지도 SDK는 Google Maps로 결정됨** (react-native-maps). 웹·v1과 동일해 로직 재사용 가능,
모바일 SDK는 지도 표시 과금 없음.

### 3. 지도 탭 구현
- `react-native-maps` 도입 (네이티브 재빌드 필요)
- 웹 `MapView.vue` 로직 이식: 같은 좌표 그룹핑 → 클러스터 마커 + 숫자
- **마커 앵커 실측값을 그대로 쓸 것** (`03_실측사실` 참조)

### 4. 루트제보 작성 화면
- 앱엔 작성 화면 자체가 없다. 웹 `ReportView.vue` 참조
- 위경도: **현재위치 버튼**(geolocation) + **지도에서 선택**(react-native-maps)
- 사진 8장, 피치 입력, GPX 업로드

### 5. 개념도 사진 + 라인 그리기 이식
웹 `ConceptPhotoEditor.vue` / `ConceptPhotoOverlay.vue` / `utils/flattenPhoto.js` 대응.
- 그리기: `react-native-svg` + `PanResponder`(RN 내장, gesture-handler 불필요)
- 합성: `react-native-view-shot` 등으로 캔버스 굽기
- **좌표 규약을 웹과 반드시 동일하게** (0~1 정규화, 선굵기 0.6%, 글자 4%)

## P2 — 출시 전 필수

### 6. 🚨 안드로이드 서명 키 (가장 위험)
- `build.gradle`의 release가 **debug 키로 서명** 중 → 스토어 거부
- v1(빌드 39)이 같은 패키지명(`com.yusung.routefinding`)으로 이미 스토어에 있다
  → **v1과 동일한 업로드 키가 반드시 필요**
- **Play Console → 설정 → 앱 서명에서 "Play 앱 서명" 켜져 있는지 먼저 확인.**
  꺼져 있는데 키를 분실했다면 같은 패키지명으로 영영 업데이트 불가
- `versionCode 1` / `versionName "1.0"` → v1보다 낮다. 스토어 최신값보다 크게 올릴 것

### 7. 웹 App Check reCAPTCHA
배포된 웹 콘솔에 `exchangeRecaptcha... 400 (Bad Request)`가 계속 찍힌다.
커스텀 도메인 `routefinding.kr`이 reCAPTCHA 사이트 키에 등록되지 않은 것으로 보임.
- Firebase 콘솔 → App Check → 웹 앱 등록 상태
- https://www.google.com/recaptcha/admin → 허용 도메인에 `routefinding.kr` 추가

지금은 App Check 강제가 꺼져 있어 데이터는 정상이지만, 강제를 켜면 앱 전체가 멈춘다.

## P3 — 개선

### 8. 썸네일 도입 (결정됨, 미착수)
목록 110x88 자리에 **원본 풀사이즈**를 넣고 있어 대역폭 낭비가 수십 배.
Firebase `Resize Images` 확장 설치 → 목록은 썸네일만 사용.
(2026-08-03에 Storage 무료 한도 1GB/일을 태워 402가 났던 이력. 지금은 Blaze 전환됨)

### 9. 웹 번들 다이어트
- `bg_splash.mp4` **3.1MB** — 첫 방문자가 그대로 받는다
- 미사용 패키지 5개: `xml2js`, `axios`, `deepmerge`, `pinch-zoom-js`, `@googlemaps/markerclusterer`
- `vuetify` 2곳에서만 참조 — CSS 515KB의 상당 부분. 실사용 확인 후 제거 검토

### 10. 등반일지 기존 기록 이관
사용자 스프레드시트(유성이_암벽등반기록, 2017~) → `climbing_logs`.
Google Drive 커넥터 재인증 필요.

### 11. 웹 git 초기화
`~/routefinding-web`은 git 저장소가 아니다. 되돌릴 수단이 Hosting 롤백뿐.

### 12. 기타
- 개념도 확대 뷰어에 라인 오버레이 미적용 (목록·상세는 정상)
- `ConceptDetailView`의 GPX 버튼(붙여넣기/복사/공유)이 빈 함수 — 살릴지 뺄지 미정
- iOS App Check를 `deviceCheck` → `appAttestWithDeviceCheckFallback` 전환 검토
- RNFB 26 + New Architecture + RN 업그레이드 (묶어서 별도 진행)
